# 01 — Problem & Goal

## The competition
**Flipkart Gridlock Hackathon 2.0 — Round 2.** ~1,635 teams. Goal: win.

## Problem statement — Event-Driven Congestion (Planned & Unplanned)
Political rallies, festivals, sports events, construction activities, and sudden gatherings create localized traffic breakdowns.

**Why it's hard today**
- Event impact is not quantified in advance.
- Resource deployment is experience-driven.
- No post-event learning system.

**Direction**
> How can historical and real-time data be used to forecast event-related traffic impact and recommend optimal **manpower, barricading, and diversion** plans?

## What a winning solution must deliver
1. **Forecast** where/when/what events will occur and how severe they'll be.
2. **Quantify impact** in advance (the brief's #1 gap).
3. **Prescribe** optimal manpower, barricading, and diversion — not just predict.
4. **Learn** after each event (the brief's #3 gap).

## How this competition is actually won
Hackathons are judged on problem understanding, technical depth, innovation, feasibility/impact, and the demo — not leaderboard accuracy alone. The edge comes from:
- A **correct reframe** of the problem (see [02 — Data Analysis](02-data-analysis.md)).
- A **prescriptive** system that allocates scarce resources, not just a predictor.
- **Kaggle-grade rigor** (time-split validation, leakage control, baselines).
- A **story-driven demo** built on a real surge day.

See [03 — Solution Architecture](03-solution-architecture.md) for the build.
